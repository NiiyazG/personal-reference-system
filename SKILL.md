# Personal Reference System — развёртывание с нуля

Навык описывает, как поставить и запустить локальную справочную систему из
репозитория `NiiyazG/personal-reference-system`. Система индексирует документы и
ищет по ним **локально, без сети**; семантический поиск и OCR реализованы и работают,
но включаются отдельным шагом — им нужны модель или пакет (см. раздел «Возможности»).

## Когда применять

- Нужно развернуть систему на новой машине.
- Нужно добавить документ в корпус или найти по нему.
- Нужно настроить путь хранилища, квоты, OCR или модель векторов.
- Система не работает: не создаётся база, поиск падает, OCR/векторы недоступны.

## Ключевые факты

- Пакет запускается как `python -m reference_system.cli`.
- Хранилище — один каталог (по умолчанию `./data`); `init` создаёт структуру, манифест
  и **пустую** базу со свободным `knowledge_base_id`.
- Поиск по пустой базе не падает — возвращает пустой список.
- Конфигурация: файл `reference.config.json` (`--config` / `REFERENCE_CONFIG`),
  переменные окружения `REFERENCE_*`, флаги CLI. Пример — `reference.config.example.json`.
- `ocr_engine` и `embedding_model` по умолчанию `none`: базовая установка ищет
  полнотекстово/точно без скачивания модели. OCR и семантический поиск включаются
  флагами (`--ocr windows`, `--embeddings bge-m3`).
- Сеть системой в рантайме не используется; модель векторов разрешается из локального кэша.

## Возможности

- **Полнотекстовый поиск (FTS5)** — работает сразу после установки, без модели.
- **Точный поиск (`--exact`)** — литеральная подстрока без учёта регистра: удобно для
  кодов вида `P-101`, `DN100`.
- **Семантический поиск (`--semantic`)** — реализовано и работает: локальная модель
  `Xenova/bge-m3` (int8 ONNX, инференс `onnxruntime` на CPU, внутри процесса,
  **без сети в рантайме**). Адаптер разрешает модель обходом локального кэша Hugging
  Face и не импортирует `huggingface_hub`/`requests`/`urllib`, поэтому «нет сети» —
  структурное свойство, а не обещание.
- **OCR (Windows)** — реализовано и работает: движок `windows-media-ocr`
  (`Windows.Media.Ocr`) вызывается **внутри процесса** через `winsdk`; ничего не
  порождается и не скачивается — распознаватель входит в состав Windows.

Семантический поиск и OCR **включаются отдельным шагом**: им нужны файлы модели или
пакет, которых нет в базовой установке. Это не «опционально» в смысле «может и не
работать» — код и тесты есть, функции работают, их нужно только включить.

### Измеренные факты

- Семантический поиск находит материал по **перефразе без общих слов** с документом
  (например, «оборудование трясётся при работе»); тот же запрос в полнотекстовом
  режиме даёт **0 попаданий**.
- Скорость: **~47 мс** на короткий фрагмент после загрузки графа; первый запуск **~3 с**
  (загрузка графа + SHA-256 файла модели).
- Модель: `Xenova/bge-m3`, int8 ONNX, 1024 измерения, 8192 токена, CLS-пулинг +
  L2-нормализация, без префиксов `query:`/`passage:`.
- Адаптер модели **не умеет скачивать**: разрешает модель обходом кэша HF и не
  импортирует `huggingface_hub`/`requests`/`urllib`.

## Известные ограничения

- Русский OCR-распознаватель подменяет латинские символы кириллическими: `P-101`
  распознаётся как `Р-1О1`. Текст хранится как выдал движок, «починки» нет — точный
  поиск по латинским кодам в OCR-тексте промахивается. Проверяйте по фактическим байтам,
  а не «улучшайте» поиск вслепую.
- `OcrEngine.max_image_dimension = 10000`: превышающая картинка уменьшается, факт
  записывается в `ocr_notes`. Увеличение по умолчанию — ошибка (масштаб 2x ломал
  `P-101` в `Р- 101`).
- `OcrWord` не отдаёт `confidence` — уверенность не сообщается.
- Слова приходят отдельными элементами без разделителей: склейка в строку даёт
  `вибрируетприоткрытии`, нужен пробел.
- WinRT-векторы не принимают отрицательные индексы (`words[-1]` → `OSError`) —
  материализовать через `list(...)`.
- Инференс векторов не бит-воспроизводим (~1e-8): проверяйте порогом (1e-5), не
  утверждайте воспроизводимость.
- `batch=1` зафиксирован намеренно: граф динамически квантизован, один и тот же текст
  в батче 1 и в батче 16 расходился до ~2e-2 на компоненту — батчинг смешал бы векторы
  запроса и хранилища.
- `model_version` — отпечаток графа, а не метка: смена квантизации, пулинга, батча или
  самого файла обязана автоматически инвалидировать векторы.
- `search --semantic` при отсутствии векторов под эту модель **отказывает с ошибкой**,
  а не возвращает пустой список (пустой список читался бы как «нет такого материала»).
- `reprocess` обязан переиндексировать векторы, иначе материал тихо выпадает из
  семантического поиска.
- `search --images` — текстовый поиск через текст страницы, **НЕ** визуальное сходство,
  без подписей и распознавания объектов.

## Шаги

### 1. Установка

```bash
git clone https://github.com/NiiyazG/personal-reference-system.git
cd personal-reference-system
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
```

Проверка:

```bash
python -m tools.security_scan
python -m unittest discover -s tests -p "test_*.py"
```

### 2. Инициализация хранилища

```bash
python -m reference_system.cli --root data init
```

Создаётся пустая база. Проверить состояние и убедиться, что поиск не падает:

```bash
python -m reference_system.cli --root data status
python -m reference_system.cli --root data search "проверка"
```

### 3. Импорт и поиск

```bash
python -m reference_system.cli --root data add "/путь/к/файлу.pdf" --title "Название"
python -m reference_system.cli --root data search "насос вибрирует"
python -m reference_system.cli --root data search "P-101" --exact
python -m reference_system.cli --root data integrity-check
```

### 4. Настройка (по желанию)

```bash
cp reference.config.example.json reference.config.json
```

Настраиваются `root`, `mode`, квоты (`total_gib`/`live_gib`/`backup_gib`/
`temporary_gib`/`minimum_free_disk_gib`), `ocr_engine`, `ocr_language`,
`embedding_model`, `allowed_profile`. Либо переменные `REFERENCE_*`, либо флаги CLI.

### 5. OCR (Windows) — включается отдельным шагом

```bash
pip install winsdk
python -m reference_system.cli --root data add scan.pdf --ocr windows
```

### 6. Семантический поиск (bge-m3) — включается отдельным шагом

```bash
pip install huggingface_hub
huggingface-cli download Xenova/bge-m3 --local-dir "$HOME/.cache/huggingface/hub/models--Xenova--bge-m3"
pip install onnxruntime tokenizers numpy
python -m reference_system.cli --root data embed --embeddings bge-m3
python -m reference_system.cli --root data search "смысл запроса" --semantic --embeddings bge-m3
```

Модель в репозиторий не входит; без неё `embed` и `search --semantic` отказывают.

## Диагностика

| Симптом | Причина / действие |
|---|---|
| `search` падает с `OperationalError` | проверьте `integrity-check`; пустой запрос из одних метасимволов возвращает `[]`, а не ошибку |
| `embed`/`search --semantic` отказывают | модель не найдена — скачайте `bge-m3` в кэш HF и установите `onnxruntime`, `tokenizers`, `numpy` |
| OCR недоступен | установлен ли `winsdk`; язык задан через `ocr_language` |
| «сканированный PDF отклонён» | подключите OCR: `--ocr windows` |
| Импорт блокируется по квоте | мало свободного места (< `minimum_free_disk_gib`) или превышен `live_gib` |
| «нашли по смыслу, не нашли по коду» | латиница/кириллица в OCR-тексте: движок подменяет латинские символы кириллическими (`P-101` → `Р-1О1`), текст хранится как есть |
| `search --semantic` падает | нет векторов под эту модель — выполните `embed --embeddings bge-m3` |
| после `reprocess` материал выпал из семантики | `reprocess` пересобрал фрагменты — нужен повторный `embed` |

## Границы

- Не публикуйте каталог `data/` — это личный корпус, он исключён в `.gitignore`.
- Удаление необратимо (резервной копии нет), требует `--confirm`.
- Не меняйте настройки Hermes и не трогайте чужие профили.
